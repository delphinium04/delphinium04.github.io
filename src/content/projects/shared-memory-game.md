'게임서버프로그래밍입문' 과목에서 C와 Linux의 프로세스 간 통신을 활용해 제작한 2인용 턴제 보드게임입니다. 뱀과 사다리를 모티브로, 주사위를 굴려 이동하고 연결된 칸이나 미니게임의 결과에 따라 전진·후진합니다.

저는 **공유 메모리의 게임 정보와 SDL2 화면 출력을 연결하는 실행 흐름을 제안**하고, 팀원의 화면 표시 기능 구현을 지원했습니다. 아래 통신 구조는 프로젝트 전체의 구성이며, 제 기여는 상태 변화가 화면에 반영되는 순서를 정리하고 함께 구동을 확인한 부분입니다.

## 문제: 바뀐 게임 정보를 언제 화면에 표시할까

공유 메모리에 게임 정보가 저장되어 있어도, 변경된 데이터를 어느 시점에 읽고 화면에 표시할지 정해져야 플레이어가 상태 변화를 확인할 수 있었습니다. 팀원이 화면 표시 기능을 구현하는 과정에서 이 연결 순서를 정리할 필요가 있었습니다.

저는 **공유 메모리의 게임 정보 갱신 → 로직 처리 → 변경된 상태의 화면 출력**을 순서대로 반복하는 실행 구조를 제안했습니다. 간단한 구동 시험으로 상태 변화에 따라 화면이 갱신되는 모습을 함께 확인하고, 팀원이 이 흐름을 바탕으로 담당 기능을 완성하도록 도왔습니다.

이 경험을 통해 데이터 전달과 화면 출력은 각자 구현하는 것만으로 끝나지 않으며, 어떤 상태를 어느 순서로 소비하는지까지 합의해야 동작이 연결된다는 점을 배웠습니다.

## 프로젝트의 실행 구조

동일한 Linux 환경에서 매니저 프로세스 하나와 클라이언트 두 개를 실행합니다. 두 플레이어는 같은 방 번호로 참여하며, 방 번호는 공유 메모리를 식별하는 키로 사용합니다. 화면 출력에는 Linux 데스크톱 또는 WSLg 환경이 필요합니다.

`GameData`에는 플레이어 위치·현재 턴·승자·게임 진행 여부·보드 연결·미니게임 구역 정보를 저장합니다. 매니저가 `shmget`으로 공유 메모리를 만들고, 클라이언트가 같은 키로 연결해 공통 게임 상태를 참조합니다.

턴은 POSIX 시그널로 진행합니다. 매니저가 현재 플레이어에게 `SIGUSR1`로 턴 시작을 알리고, 클라이언트는 이동과 미니게임을 마치면 `SIGUSR2`로 종료를 알립니다. 매니저가 승리 조건을 확인해 다음 턴을 정하며, 게임 종료 알림에는 `SIGINT`를 사용합니다.

클라이언트는 `fork`로 SDL 화면 담당 자식 프로세스를 만들고, 두 방향의 파이프로 클릭 입력과 안내 메시지를 전달합니다. SDL2는 보드와 캐릭터를 그리고, SDL2_image는 PNG 이미지를, SDL2_ttf는 한글 안내를 표시합니다. 미니게임 답변은 터미널에서 입력하고 안내와 결과는 SDL 화면에 표시합니다.

## 플레이 흐름

자신의 차례에 화면을 클릭하면 1–6의 주사위 값만큼 이동합니다. 문어 다리가 연결된 칸에서는 지정 위치로 이동하고, 미니게임 구역에서는 퀴즈·타이핑·업다운 중 하나가 선택됩니다. 미니게임 성공 시 1–2칸 전진하고 실패 시 1–2칸 후진합니다. 매니저가 도착 여부를 판정하고 각 화면에 승패를 표시합니다.

## 결과

공유 상태의 갱신부터 화면 출력까지 이어지는 실행 구조를 구동 시험으로 함께 확인했고, 팀원이 화면 표시 기능을 완성할 수 있도록 지원했습니다. 프로젝트는 기한 내 제출했으며, '게임서버프로그래밍입문' 과목에서 <strong>A+</strong>를 받았습니다.
