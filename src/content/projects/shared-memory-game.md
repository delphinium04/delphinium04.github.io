> 두 플레이어가 주사위를 굴려 보드를 이동하고, 문어 다리와 미니게임을 거쳐 먼저 도착 지점에 도달하는 2D 턴제 보드게임입니다. 주사위의 무작위성과 퀴즈·타이핑·숫자 맞히기 결과에 따른 이동 변화를 결합했습니다.

## 1. 프로젝트 개요

2024년 2학기의 **게임서버프로그래밍입문** 수업에서 기말고사 과제로 진행한 팀 프로젝트로, 고전 보드게임 '뱀과 사다리'를 모티브로 제작했습니다. Linux의 프로세스 간 통신(IPC) 기능을 게임 진행 전반에 활용하며, 매니저 프로세스가 시그널을 사용해 시작과 턴 전환을 통제하고 두 클라이언트가 공유 메모리를 통해 동일한 게임 상태를 참조합니다.

아래 통신 아키텍처는 팀 전체의 구현 결과물이며, 그중 저는 **공유 메모리의 게임 정보 갱신 → 로직 처리 → 변경된 상태의 SDL2 화면 출력으로 이어지는 반복 실행 구조를 제안**하고 구동 시험으로 동작을 함께 확인해 담당 팀원이 화면 표시 기능을 완성할 수 있도록 지원했습니다.

### 게임 진행

1. 매니저에서 방 번호를 정하고, 두 클라이언트가 같은 번호로 참여합니다.
2. 자신의 차례에 게임 화면을 클릭하면 1~6 범위의 주사위 값만큼 이동합니다.
3. 문어 다리가 연결된 칸에 도착하면 지정된 다른 칸으로 이동합니다.
4. 미니게임 구역에서는 **퀴즈·타이핑·업다운** 중 하나가 무작위로 선택됩니다.
5. 미니게임 성공 시 1~2칸 전진하고, 실패 시 1~2칸 후진합니다.
6. 매니저가 도착 여부를 판정하고, 각 플레이어의 화면에 승패 결과를 표시합니다.

### 실행 환경

- 동일한 Linux 환경에서 **매니저 프로세스 1개**와 **클라이언트 프로세스 2개**를 실행하는 구조입니다.
- 방 번호는 System V 공유 메모리를 식별하는 키(`key_t`)로 사용합니다.
- 그래픽 창을 표시하려면 Linux 데스크톱 또는 Windows의 **WSLg** 환경이 필요합니다.

## 2. 주요 구현

### 문제 해결: 바뀐 게임 정보를 언제 화면에 표시할 것인가

공유 메모리에 게임 상태가 기록되어 있더라도, 그래픽 담당 프로세스가 어느 시점에 데이터를 읽고 다시 그릴지 정해지지 않으면 플레이어는 말의 이동이나 턴 변화를 확인할 수 없었습니다. 화면 출력을 맡은 팀원이 이 연결 순서를 잡는 과정에서 어려움을 겪고 있어 전체 실행 순서를 명확히 정리할 필요가 있었습니다.

저는 **공유 메모리의 게임 정보 갱신 → 로직 처리 → 변경된 상태의 화면 출력**을 한 주기로 묶어 순서대로 반복하는 실행 구조를 제안했습니다. 간단한 구동 시험을 통해 상태 변화에 따라 창이 정상적으로 갱신되는 모습을 함께 확인했고, 팀원이 이 흐름을 바탕으로 보드와 연출 기능을 완성하도록 도왔습니다.

이 경험을 통해 프로세스 간 데이터 전달과 그래픽 출력은 각자 구현하는 것만으로 끝나지 않으며, **어떤 상태를 어느 순서로 소비할지까지 합의해야 비로소 동작이 하나로 맞물린다**는 점을 배웠습니다.

---

### 공유 메모리를 이용한 게임 상태 공유

- 공통 구조체인 `GameData`에 **플레이어 위치, 현재 턴, 승자, 게임 진행 여부, 보드 연결 정보(문어 다리), 미니게임 구역 정보**를 저장합니다.
- 매니저가 `shmget`으로 공유 메모리 영역을 생성하고, 두 클라이언트가 동일한 방 번호로 해당 영역에 연결(`shmat`)합니다.
- 이 구조에서 매니저는 전체 진행 상태를 관리하고, 클라이언트는 자신의 이동과 미니게임 결과를 공유 메모리에 반영하며, 화면 자식 프로세스는 해당 상태를 읽어 화면을 갱신합니다.

### 시그널을 이용한 턴 진행

- 매니저는 현재 차례의 클라이언트에 턴 시작 시그널을 보냅니다.
- 클라이언트는 주사위 이동과 미니게임 처리를 마친 뒤 매니저에게 턴 종료 시그널을 보내며, 매니저는 승리 조건을 확인하고 다음 플레이어의 차례를 지정합니다.
- 턴 시작에는 `SIGUSR1`, 턴 종료에는 `SIGUSR2`, 게임 종료 알림에는 `SIGINT`를 사용합니다.

### SDL2 화면과 게임 로직의 분리

- 각 클라이언트는 `fork`로 SDL 화면을 전담하는 자식 프로세스를 생성합니다.
- 게임 로직(부모 프로세스)과 화면(자식 프로세스) 사이에는 방향별로 **두 개의 파이프(Pipe)**를 두어 마우스 클릭 입력과 안내 메시지를 주고받습니다.
- `SDL2`로 보드와 캐릭터를 그리고, `SDL2_image`로 PNG 에셋을 불러오며, `SDL2_ttf`로 한글 안내 문구를 출력합니다. 미니게임 안내와 승패 결과도 별도의 이미지로 표시합니다.

### 세 가지 미니게임

미니게임 구역에 도착하면 아래 세 가지 중 하나가 무작위로 실행됩니다. 답변은 터미널에서 입력하고, 문제 안내와 성공·실패 결과는 SDL 그래픽 창에 표시됩니다.

- **퀴즈** — CSV 파일에서 문제·선택지·정답 정보를 읽어오고, 사용자가 입력한 답과 정답을 비교합니다.
- **타이핑** — 무작위로 제시된 문장을 입력받아 문장의 일치 여부와 입력에 걸린 시간을 확인합니다. 입력 완료 후 **10초 초과 여부**를 기준으로 성공·실패를 판정합니다.
- **업다운** — 1~50 사이의 숫자를 맞히는 게임입니다. 최대 5번의 입력에 대해 높고 낮음(Up/Down)을 안내하고, 5번 안에 정답을 맞히지 못하면 마지막 추가 입력이 **정답의 ±5 범위** 안에 들어오는지 확인합니다.

## 3. 프로젝트 결과

공유 상태의 갱신부터 화면 출력까지 이어지는 실행 루프를 구동 시험으로 함께 검증하며 팀원의 그래픽 파트 완성을 도왔습니다. 프로젝트는 기한 내에 완주 가능한 상태로 제출했으며, **게임서버프로그래밍입문** 과목에서 **A+** 성적을 받았습니다.
